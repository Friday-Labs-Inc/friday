Friday — End-to-End Testing Guide

How to configure and verify every delivered feature · live target: ai.randompack.com

Friday is an enterprise agentic-orchestration framework: AI agents are first-class actors that run governed, audited, durable work. This guide is for testing what's been delivered — each feature has What it is, How to test, and Expected result. You work in two places:

  • Desk (/app, log in as Administrator) — configure agents, providers, cron jobs, roles, Slack.
  • Raven (/raven) — chat with and control agents. The primary "talk to your agents like coworkers" surface.

1 · Talk to an agent core

What: message the Friday bot in Raven; it answers as a real governed agent (thinks, uses tools, replies).

Test: open a DM with Friday → "What can you help me with?"

Expect: a real reply authored by the agent. This is the foundation everything rides on.

2 · Run real project work

What: agents create Projects + Tasks, run a durable pipeline (dispatch → run → auto-heal), and produce downloadable deliverables (Markdown + PDF).

Test: ask an Orchestrator "Draft a one-page brief on X and save it." Watch Desk: Task list + the Task Pipeline Kanban.

Expect: Tasks move Pending → Assigned → Executing → Completed; a finished task attaches real deliverable files.

3 · The human-approval gate — from chat governance

What: a risky action pauses and waits for a human; you approve/deny from Raven.

Test: when an agent hits a gated action it posts that it needs approval (a Workflow Request goes Pending). Type /approve (or /approve <id>), or /deny too risky.

Expect: /approve flips the request to Approved and resumes the paused work; /deny rejects + records the reason. (AWS-verified.)

4 · Control a running agent — slash commands

/status and /help are open to anyone; the rest need Friday Operator.

CommandDoesExpect
/helpList commandsBot posts the list
/statusThis channel's state"N pending approval(s)"
/approve · /denyThe gate (§3)Resumes / rejects
/stopInterrupt the turn + its delegated work"🛑 Stopping this turn and N delegated task(s)"
/stop forceHard-kill a wedged turn now"💀 Force-killed: N job(s) cancelled"; tasks → ForceKilled
/steer <text>Nudge a running turn without stopping itAgent adapts on its next step
Not a bug: /stop and /steer take effect at the agent's next thinking step (after its current model call), not mid-sentence. Use /stop force only when a turn is wedged inside one long operation. A plain message sent while busy queues — only the commands interrupt.

5 · Scheduled agent runs — Cron Jobs ⏰

What: "run agent X with prompt P on schedule S, deliver result to T." A scheduled run is a normal durable Task underneath.

Test (Desk): new Cron Job → an Agent Profile, prompt "Summarise today's completed tasks", Schedule Kind=interval, Schedule Expression=1 (every minute), Deliver To=local.

Expect: within a minute a Task spawns + runs; the result is saved as a private File (open via the job's Last Task). Switch Deliver To to raven:<channel-id> → it posts into that channel. Repeat Times=1 → auto-disables after one run.

Heads-up: results aren't visible until ≥1 scheduler minute passes — don't read too early.

5b · Agents schedule their own work NEW

Test (Raven): ask an agent "schedule a job to post a status summary into this channel every 2 minutes." Then "list my scheduled jobs" and "pause/remove that job."

Expect: the agent uses the manage-cron-jobs skill → a Cron Job appears owned by that agent, delivering to the channel; within the interval the summary posts. An agent can only manage its own jobs.

6 · Search past conversations — session_search NEW

What: a long-lived agent can search its own past Chat Message history by full text — "what did we decide about X last week?"

Test (Raven): after some conversation, ask the agent "search our past messages for <a keyword you used earlier>."

Expect: the agent calls session_search and returns ranked past messages (content + session + time). Scoped to that agent's own messages only.

7 · Second chat surface — Slack NEW

What: Friday on Slack too — a thin adapter writing the same Chat Message rows as Raven. Proves the gateway is multi-surface.

Setup (one-time, external):

  • Create a Slack app; add a bot token (xoxb-…) + the signing secret to Slack Config in Desk; set bot_user_id + default_agent_profile; enable.
  • Point the app's Event Subscriptions request URL at:
    https://ai.randompack.com/api/method/frappe.friday_core.surfaces.slack_adapter.receive_event
    Subscribe to message.im and app_mention.

Test: DM the Slack bot, or @mention it in a channel; try /help and /approve there too.

Expect: the bot replies in Slack exactly like Raven; slash commands work; the request signature is verified (a forged request is rejected).

What's NOT in scope yet (set expectations)

  • A2A (agent-to-agent protocol) — deferred.
  • External memory providers (Mem0) — deferred; first-party pgvector covers semantic recall.
  • Lifecycle-hook plugins — deliberately not built (Friday already emits lifecycle events internally).
  • Polish: live token streaming, per-surface display tiers, out-of-turn transcript mirroring.

The Hermes → Friday port is complete: every functional capability is shipped and on main. The items above are justified deferrals or polish, not gaps.
