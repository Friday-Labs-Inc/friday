# A2A inbound v1 — Friday as a governed agent-to-agent node (2026-06-26)

## What shipped

Friday can now be **driven by other agents** over Google's A2A (Agent2Agent) protocol —
and, true to the campaign, it does so as a **governed** peer, not a raw one. This is the
third interoperability surface, alongside the chat surfaces (human↔agent) and the MCP
server (tool-client↔agent).

A remote agent does two things:

1. **Discovers Friday** — `GET /.well-known/agent.json` returns an Agent Card listing
   exactly the exposed profile's permitted skills (built from the same loader the agent
   runs with, so it can't over-advertise).
2. **Sends it work** — `POST …/a2a.server.handle` with a JSON-RPC `message/send`. Friday
   runs one turn as the configured Agent Profile and returns the reply as a completed
   A2A task.

## Why it matters

The turn behind `message/send` is NOT a raw tool call. It runs through Friday's real
agent loop — `run_turn` → permission **matrix** → dispatcher → **Execution Log** audit →
human **approval gate**. So an external agent gets exactly the access the exposed profile
has, every turn is recorded, and a gated skill still pauses for a human. An enterprise
can let a partner's agent talk to Friday without handing over ungoverned access. That's
the whole point.

## How it's built (reuse, not reinvention)

It mirrors the MCP server almost line-for-line:

- `a2a/server.py` — a pure `handle_jsonrpc` core (injectable backends → 23 DB-free
  tests) behind a thin whitelisted endpoint. `X-A2A-Token` header auth (NOT
  `Authorization: Bearer` — Frappe's middleware rejects unknown Bearers before the
  endpoint runs; the MCP server learned this live on the box). Raw JSON-RPC response body.
- `a2a/card.py` — pure Agent Card builder; skills from `load_for_profile`.
- `a2a/task_store.py` — a lightweight Redis task store (`submitted → working →
  completed | failed | canceled`), deliberately NOT the heavy `Task` doctype.
- `A2A Server Settings` single doctype — `enabled` (off by default), `agent_profile`,
  encrypted `auth_token`. Mirrors `MCP Server Settings`.
- One inline branch in `app.py` serves the card at the spec's `/.well-known/agent.json`,
  mirroring the existing `security.txt` special-case.

The sync turn calls `run_turn` directly, so there is **no** new Chat Platform row and
**no** `after_migrate` provisioning — fewer moving parts than the gateway path.

## Locked decisions (v1)

Static-token auth · sync dispatch (reply inline) · `session_id` = the A2A `taskId` · one
global Agent Card · Redis task store. See [docs/design/92-a2a.md](../design/92-a2a.md)
for the rationale and the v2 deferrals (outbound `call-a2a-agent` skill, streaming,
per-request HMAC, per-profile cards).

## Safety

Disabled by default — both the endpoint and the card 404 until an operator enables the
single, sets the token, and picks the exposed profile. Fail-closed auth (no token →
unreachable even if enabled). Enabling it is a deliberate external-surface-activation
decision, never automatic.

## Verifying it (once enabled on a box)

```
GET  /.well-known/agent.json                         → the Agent Card (Friday's skills)
POST /api/method/frappe.friday_core.a2a.server.handle
     X-A2A-Token: <token>
     {"jsonrpc":"2.0","id":1,"method":"message/send",
      "params":{"message":{"role":"user","parts":[{"type":"text","text":"…"}]}}}
                                                      → {result:{id, status:{state:"completed"}, artifacts:[…]}}
```
An Execution Log row for that turn proves governance fired. An unsigned/garbage
`X-A2A-Token` returns 401 before any turn runs.
