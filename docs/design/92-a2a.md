# Design 92 — Friday as a governed A2A node (v1, inbound)

Status: LOCKED + built (v1, inbound). Branch off main; surface disabled by default.

## What this is, in plain English

Friday already talks to humans (chat surfaces), and already speaks **MCP** both ways
(it calls remote tools, and it *serves* its own skills as governed MCP tools — Design
67 / #159). This adds the third interoperability surface: **A2A — agent-to-agent**.

Another agent framework that speaks Google's [Agent2Agent protocol](https://github.com/google/A2A)
can now **discover Friday** (fetch its Agent Card) and **send it work** (a JSON-RPC
`message/send`). Friday answers as one of its Agent Profiles.

## The whole point: a GOVERNED peer

An ordinary A2A node runs the request directly — ungoverned. Friday does not. An
inbound `message/send` runs through Friday's **real agent loop** (`run_turn` →
permission **matrix** → dispatcher → **Execution Log** audit → human **approval
gate**). The calling agent gets exactly the access the exposed Agent Profile has — no
more — and every turn it triggers is recorded. That is the enterprise value: a
governed, audited agent peer, not a raw one. (Same thesis as the MCP server.)

## v1 scope

**INBOUND only.** Friday answers A2A and serves its Card. OUTBOUND (Friday calling
*other* agents' A2A endpoints) is deferred — it becomes a governed `call-a2a-agent`
skill in the dispatcher's registry, built in a later slice, so even Friday-as-caller
stays on the matrix + audit.

Methods: `message/send`, `tasks/get`, `tasks/cancel`. Scoped out of v1: streaming,
push notifications, multi-turn task history, per-profile cards.

## The five locked decisions

| # | Decision | Choice (v1) | Why |
|---|---|---|---|
| 1 | Auth | Static token in **`X-A2A-Token`** header | Parity with the MCP server. A custom header sidesteps Frappe's `validate_auth`, which 401s any unknown `Authorization: Bearer` *before* a whitelisted endpoint runs (the trap the MCP server hit live). Per-request HMAC is a v2 hardening when external orgs call Friday. |
| 2 | Dispatch | **Sync** — `message/send` returns `state=completed` inline | Short conversational turns. `run_turn` already blocks and returns the reply; no async Chat Message queue needed. One field-flip to async later. |
| 3 | `session_id` | **= the A2A `taskId`** | Each A2A task is its own conversation (task-scoped memory/history). Persistent cross-call sessions are a deliberate v2 feature, not a default. |
| 4 | Agent Card | **One global card** from the configured profile | Simple discovery. Per-profile cards (`?profile=…`) are v2. |
| 5 | Task tracking | **Lightweight Redis store** keyed by `taskId` | A conversational turn is request/response — it does NOT need the heavy Friday `Task` doctype (dispatcher, reconciler, dependency graph). When A2A later delegates real *project* work, THAT is when a `taskId` maps onto a `Task`. |

## How it reuses what exists (no new machinery)

- **Endpoint** `a2a/server.py` mirrors `mcp/server.py` exactly: a `@frappe.whitelist(allow_guest=True, methods=["POST"])` endpoint, a pure `handle_jsonrpc(...)` core (injectable `run_fn`/`store`/`new_id`, so it is unit-testable with no Frappe/DB/LLM), `X-A2A-Token` auth via `hmac.compare_digest`, and a raw `werkzeug.Response` body (not Frappe's `{"message": …}` wrapper).
- **The governed turn** is `run_turn(profile, session_id, text)` — the same primitive the gateway and the eval harness drive. Calling it directly gives us a governed *sync* turn for free.
- **The Agent Card** `a2a/card.py` builds its `skills[]` from `skills.loader.load_for_profile` — the SAME loader the agent runs with, so the card advertises exactly the profile's permitted, matrix-scoped skills and never leaks more.
- **Discovery** is served at the spec's canonical `GET /.well-known/agent.json` via one inline branch in `app.py`, mirroring the existing `security.txt` special-case (kept out of the OAuth module).
- **Settings** `A2A Server Settings` (single doctype) mirrors `MCP Server Settings`: `enabled` (Check — **off by default**, so a fresh install advertises nothing and 404s), `agent_profile` (Link), `auth_token` (Password, encrypted). No Chat Platform row and no `after_migrate` provisioning needed (sync `run_turn` doesn't route through the gateway).

## Files

```
a2a/server.py        handle_jsonrpc core + handle() POST + agent_card() GET (mirrors mcp/server.py)
a2a/card.py          build_agent_card(profile) — pure, skills from load_for_profile
a2a/task_store.py    A2ATaskStore — Redis-backed submitted→working→completed|failed|canceled
doctype/a2a_server_settings/   single: enabled / agent_profile / auth_token (off by default)
app.py               + one branch routing /.well-known/agent.json → a2a.server.agent_card
tests/test_a2a.py    23 DB-free tests: store, card, governed message/send, tasks/*, routing, auth
```

## Security posture

Disabled by default (enabled=0 → 404 on both the endpoint and the card). When enabled,
fail-closed auth (no token configured → unreachable even if enabled). The exposed
profile bounds the blast radius — an external caller can only reach that profile's
matrix-permitted skills, and gated skills still pause for human approval. Enabling the
surface, setting the token, and choosing the profile are deliberate operator actions
(the external-surface-activation boundary), never provisioned automatically.

## What's NOT done in v1 (named, not silent)

- OUTBOUND (`call-a2a-agent` skill) — deferred to a later slice.
- Streaming / push / multi-turn task history / per-profile cards — v2.
- Per-request HMAC auth — v2 hardening.
- `tasks/cancel` mid-flight interruption — v1 turns complete synchronously, so cancel is idempotent on an already-terminal task; true mid-run cancel arrives with async dispatch (Decision 2 flip) + the `/stop` flag wiring.
